# Slice 2 design v3.1: three amendments, all accepted

**S2-1c, retention.** The project mirror is a plain bare repository, not a `--mirror` clone, with no default fetch mapping. Every fetch names its source ref and a destination under `refs/relay/incoming/`. Before the oracle runs, the verified candidate commit is pinned at `refs/relay/pins/<commit>`, and the pin lives as long as the evidence that names it. Relay never fetches into, prunes or overwrites `refs/relay/pins/`. Every push names exactly one destination ref. Trusted Git runs with replacement objects disabled, so a recorded hash names the tree actually exported. Test: verify green on A, move the remote attempt to B, restart before publication, expire unreachable objects in the mirror, publish A from the pin, and check an unrelated remote ref is untouched. Loss of the mirror itself follows the blocked-recovery path.

**S2-5b, releasing an intent.** A remote rejection settles the intent and releases the project slot only when it is the outcome of the first send, with no earlier send whose result is unknown. If any earlier send may still complete, the intent stays outstanding and is reconciled from trunk: the candidate means it converged; a head beyond the expected base that is not the candidate is a conflict and fences the old push; the expected head alone proves nothing and the slot stays occupied. Abandonment in that last state is not offered in this slice. Tests: your two-barrier case (A held at the remote, B rejected, slot still occupied, A released, one integration record) and the single-rejection case, which does release the slot.

**S2-4b, duplicate requests.** An integration request carries a request id. A retry with the same id gets the existing batch or intent receipt. Only a request with a different id, or changed inputs, supersedes a batch. Test: lose the response, retry, and the original batch still authorises the integration.

With these, 2a is being built. 2b starts only after 2a is accepted.
