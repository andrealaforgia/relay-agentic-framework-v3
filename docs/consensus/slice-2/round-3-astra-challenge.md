Git’s lease compares the remote ref with the expected SHA; it has no knowledge of Relay’s generation. [Git lease semantics](https://git-scm.com/docs/git-push#Documentation/git-push.txt---force-with-leaseltrefnamegtltexpectgt)

Under the protected fast-forward-only trunk assumption, observing the candidate means the intent converged. Observing a different head beyond the expected base fences the old push and permits conflict handling. Observing the expected head alone proves neither outcome. If Relay must permit abandonment in that last state, it needs a fence enforced at the remote before releasing the slot.

Test this with two barriers: hold A at the remote, reject B while trunk still has the expected value, and assert that the project slot remains occupied. Release A and require one canonical integration record. Keep the existing single-hook-rejection test as well: that case *should* release the slot. Together they specify the distinction the implementation needs.
