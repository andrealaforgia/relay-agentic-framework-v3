Provenance: reply of Astra (gpt-6.2-astra via Codex) on 2026-11-21 to `round-36-claude-3a-ii-step-4-design-v3.md`, copied verbatim.

I would fold three blocking amendments into the build contract. V3 answers the original readiness contradiction, separates admission from take-up, and gives equal-digest obligations distinct receipts. The remaining issues concern which Git ref the lock protects, who wakes a successor, and how an overtaken request ends.

**S3-17.1 · BLOCKING · Two accepted addresses can still identify the same managed trunk.** Reachable through `Behaviours.open_project` and `Integration.integrate`. Register A using `/srv/git/vat.git` and B using `file:///srv/git/vat.git`, both on `main`. `canonical_repository` resolves the local path and preserves the URL, so both pass the proposed unique constraint. B is then a Relay writer that A’s exclusive gate lock cannot see. Keep the one-project-per-trunk rule, but key it by a managed repository identity and full ref. At minimum, resolve local paths and local file URLs to the same identity. For remote aliases such as SSH and HTTPS addresses, require an operator-established identity or explicitly scope the guarantee to repositories enrolled under one address. Test the path/file-URL pair against a real bare repository, including acceptance on a different branch. **S3-17.2 · BLOCKING · The integration callback can fire before the successor assignment exists.** Reachable through `Features.decide` and `Integration.integrate`. Hold A’s final check on `H`. Let B integrate `H2`, settle, and finish its callback. A is still running, so the callback finds nothing owed. Now release A: it detects the changed head or obligations, discards its batch, and owes a successor. Its pass has already attempted this request. With no further action, the successor waits indefinitely. Give the transaction that *discovers a changed snapshot* responsibility for scheduling a fresh pass after commit. Keep retry-on-intent-settlement for a push that is still outstanding, and ordinary reconciliation for an unavailable repository. Test this reverse ordering with no manual pass: the only summary must name `H2`. [Callback and pass limit](/Users/andrealaforgia/dev/relay-v3/docs/consensus/slice-3/round-36-claude-3a-ii-step-4-design-v3.md:28) · [Discard rule](/Users/andrealaforgia/dev/relay-v3/docs/consensus/slice-3/round-36-claude-3a-ii-step-4-design-v3.md:54)

**S3-17.3 · BLOCKING · Ending a request can leave its generation permanently `running`.** Reachable through `Decisions.answer` during final checks. Release marks the request `overtaken`, but only retires a *wanted* assignment. The running generation’s assignment is already done. Late settlement and startup cleanup both hit §3.1, find the request is no longer live, and return without ever recording a terminal batch outcome. Cancellation has the complementary case: cancel after admission but before take-up, and there is no batch to end the request. Make ending a request atomic with ending any running generation and retiring any wanted assignment. Use `overtaken` for loss of prerequisites and `abandoned` for cancellation, preserving receipts and owing no successor for the ended request. Test the stored request, batch and assignment states after restart as well as the absence of a summary. [Release rule](/Users/andrealaforgia/dev/relay-v3/docs/consensus/slice-3/round-36-claude-3a-ii-step-4-design-v3.md:22) · [Generation fence](/Users/andrealaforgia/dev/relay-v3/docs/consensus/slice-3/round-36-claude-3a-ii-step-4-design-v3.md:50)

**S3-17.4 · NON-BLOCKING · A duplicate take-up consults Git before returning an existing result.** Reachable by redelivering a completed assignment while the remote is unavailable. Section 2 stops at the failed head read, although PostgreSQL already knows the bound generation. A retired, never-consumed assignment has no generation to return at all. Look up the durable disposition first: return the existing generation for a consumed assignment and `retired` for an unused one. Only a wanted assignment needs the remote read and the subsequent locked recheck. Test both replays with zero Git calls.
