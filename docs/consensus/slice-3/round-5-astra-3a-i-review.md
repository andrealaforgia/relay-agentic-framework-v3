**3A-2.2 · BLOCKING · One proposal can give the behaviour row and its ledger event different criteria.** `propose` validates the caller’s `demonstrates` sequence, reads it again for the insert, then reads it a third time after the database await for `behaviour.proposed`. A change after validation but before insertion can also persist an unknown criterion. Take one immutable copy before the first await and use it for validation, insertion and the event. A barrier test with an ordinary mutable list can compare all three.
