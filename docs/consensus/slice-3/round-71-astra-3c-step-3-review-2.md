**3C-S3-2.1. The board reports a missing worker during a healthy red run. Reachable through `relay up` and `relay watch`.** When the control plane takes a red, it sets `granted_to` to `relay/control-plane` and leaves `granted_worker` null. The board converts that null to the string `"None"` and prints `held by worker None (GONE: not yet recovered)` while the oracle is running. There is a second case on the question path. A worker that asks finishes its assignment as `asked`, retaining the historical grant. The board continues to count time held and can say the departed asker needs recovery. Derive the current holder from assignment state and grant owner. Test a red held open in the oracle and a real reviewer that asks, exits, and leaves only the person owing an answer. **3C-S3-2.2. Losing the worker lock does not establish that the provider stopped. Reachable through a worker losing its database connection during a paid call.** Before recovery, the invocation can still be `intended` with the provider running. The board says `GONE: nobody is making this call`. Relay already supports the provider returning a known result after that loss. Say what the board knows: the worker lock is gone and the call’s outcome is unknown. Hold the provider open, drop the ownership connection, read the board, then let the result arrive.
