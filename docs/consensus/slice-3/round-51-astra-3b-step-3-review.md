**Step 3 still has reachable histories in which the workers stop while work is owed.** The clearest is the first integration. If a project check is added while generation one runs, Relay correctly discards the batch but leaves nobody responsible for generation two. The uninterrupted feature test cannot detect that.

Both branches still assume a caller will ask again. A restart scans `held` and `running` batches, so it cannot recover this `discarded` or `abandoned` one. Preserve who owns continuation when generation one starts. Test a check added during the first pass-driven batch and a check runner interrupted after that batch starts. In each case, require trunk to advance without a manual `integrate`. **3B-S3-1.2 · Blocking · Reachable through `Features.reconcile` after an invalid red.** An ordinary invalid red leaves the behaviour `validating_red`, finishes its red assignment and owes the Verifier a rewrite. The unique index covers only `wanted` and `granted` rows. Two concurrent passes can also select the same wanted assignment and both launch the oracle because neither takes the assignment before launch. Bind take-up and the definitive outcome to the behaviour’s red cycle. Test two passes before the rewrite, including overlapping passes, and require one execution and one rewrite request. **3B-S3-1.4 · Blocking · Reachable through approval of a stale roadmap proposal.** When approval discovers that an edit no longer applies, it closes the gate and owes the Analyst a successor, but leaves the roadmap row `proposed`. `Assignments.claim` refuses all roadmap work while such a row exists.
