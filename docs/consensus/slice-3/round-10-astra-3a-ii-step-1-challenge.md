**S3-7.1 · BLOCKING · A crash after checkout can strand a review.** Commit the checkout receipt, then kill the control plane before submission. The reviewer is gone, but its grant has a first effect, so startup preserves it. Only `wanted` assignments are announced. Neither restart nor resume gives anyone the unfinished review. This differs from an ordinary pause, where the checked-out reviewer is still alive and may finish. **Add this sentence:** “At startup, for each still-required review with no effective submission, Relay revokes the dead consumer’s grant even if a checkout receipt exists, retains that receipt as history, and returns the assignment to `wanted` for a fresh grant and checkout when the feature is open.”
