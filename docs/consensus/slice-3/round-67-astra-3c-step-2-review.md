**3C-S2-1.1 · An expired code can still decide. Reachable through `relay confirm`.** Open the prompt before the hour ends and enter the passphrase afterwards. `_confirm` checks expiry once, before printing the prompt. It then carries out the decision without checking the code again. A second terminal can even have the code recorded as expired while the first is waiting. In the isolated command check, `carry_out` was called once after expiry and the command exited zero. Check expiry and consume the code in the transaction that decides. Both terminals should subsequently get the same outcome. [Confirmation](</Users/andrealaforgia/dev/relay-v3/src/relay/cli/main.py:526>) · [Prepared action record](</Users/andrealaforgia/dev/relay-v3/src/relay/application/prepared.py:65>)

**3C-S2-1.2 · A code can select its own project. Reachable through `relay confirm`.** Prepare in A, select B through `RELAY_PROJECT` or B’s checkout, then confirm without `--project`. The command passes A to the selector as an explicit choice, overriding B. Once the code has a receipt, even `--project B` returns A’s receipt before checking the project. Resolve the person’s project first and enforce the match for both first confirmation and replay. This is distinct from an exact `--request-id` replay, which is meant to remember its original project. [Project check](</Users/andrealaforgia/dev/relay-v3/src/relay/cli/main.py:513>) · [Selector](</Users/andrealaforgia/dev/relay-v3/src/relay/cli/selection.py>)

It also returns zero when replaying a *stale* receipt whose original exit status was one. Compare the request with its recorded project, verb, target and arguments before returning the receipt. An exact replay must still work with the gate closed and no terminal. The pause identity fixes a resume applied to a *later pause*. It does not distinguish two periods when the feature was open. Bind cancellation to the latest relevant transition and check it under the feature lock.
