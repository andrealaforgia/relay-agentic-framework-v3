## B. Architecture Proposal v1

**Threat model.** One Product Owner. Enrolled, operator-controlled worker hosts. Repository contents, model output, test output and tool output are untrusted. Hostile multi-tenant operation is out of scope.

**Processes.** `relay-control` (async Python): authenticated HTTP API, FSMs, scheduler, outbox publisher, lease reaper and reconciler, integration controller, SSE for the dashboard. `relay-worker` (one daemon per host): enrols, advertises capability pools, consumes its pools' command streams, runs provider adapters or the model-free evidence runner. PostgreSQL and Redis as services (Docker Compose). `relay` CLI talks only to the API.

**Capability pools.** A pool is (role, provider) or `runner`. Stream per project and pool: `relay:{project}:cmd:{pool}`, one consumer group per stream. Event stream `relay:{project}:events` with one group per independent subscriber. QA and Sentinel are separate addressed tasks on the same candidate SHA.

**PostgreSQL.** Your logical table outline is accepted as the target. Built incrementally: slice 1 creates only projects, runs, stories, behaviours, events, outbox, workers, tasks, attempts, artefacts, executions. Plain SQL migrations, no ORM. `events` is append-only with unique (project, sequence) allocated under a project advisory lock.

**Evidence.** As in my F1 to F3 positions. Gate-bearing executions are accepted only from an enrolled `runner` identity.

**Provider adapters.** Async subprocess adapters over `claude -p --output-format stream-json` with `--json-schema`, and `codex exec --json` with `--output-schema`. Prompt on stdin. Process-group kill on timeout or cancel. Usage parsed from both CLIs where reported, recorded as observed; price estimates are a separate, versioned-table computation; anything not reported is `unknown`. The canonical `alf-*` definition is passed as the role's instructions (Claude: `--agent` or appended system prompt from the Markdown body; Codex: the TOML `developer_instructions`), with path, repository revision and sha256 recorded.

**Product Owner entry point.** The interpreter runs as an ordinary worker task. Its questions land in the central inbox. The Product Owner answers through `relay answer` or through a thin Claude Code skill that calls the same CLI. No pty-held session, no hook-delivered mail. Subject to Product Owner confirmation.

**Deliberate reductions for now.** One active story. Two adapters (pytest, JUnit XML). One Git route (configured remote, ref namespaces). Bounded artefacts in PostgreSQL. Single control-plane instance. No adaptive routing, no native session continuation, no hosted-CI integration, no searchable log export.
